# 功能与架构说明

本文描述 TileZhan / TileSlash 当前已经进入代码的主要功能、数据边界和发布策略。商店审核状态会变化，应始终以 App Store Connect 和 Google Play Console 为准。

## 总体架构

```text
Flutter UI
   │
   ├── Riverpod 状态与领域逻辑
   │      ├── 训练计划 / SRS / 弱项模型
   │      ├── 何切 / 防守 / 役种 / 手牌分析
   │      └── 商业功能可用性策略
   │
   ├── Hive / StorageService（设备本地持久化）
   │
   └── Dio 网络层 ── Firebase Bearer Token ── FastAPI
                                                 ├── Firebase / Firestore
                                                 ├── RevenueCat
                                                 └── Redis / Celery
```

客户端采用离线优先设计。每日计划、SRS、何切掌握度、防守进度和手牌分析历史都有本地持久化边界；后端用于需要身份、跨设备或服务端可信计算的能力。

## 每日训练计划

每日计划把训练拆为稳定、可恢复的本地任务：

- SRS 到期复习
- 闪卡练习
- 每日何切挑战
- 防守训练
- 役种测验
- 在数据足够时生成的弱项专项任务

计划按本地日期生成并带版本号，完成进度会持久化。训练页面只有在一次作答被接受后才记录进度，随后显式刷新本地存储，避免 UI 已显示完成但数据尚未落盘。

弱项推荐不会因为一次错误就下结论；系统根据何切教学标签和防守技能的累计表现选择可靠弱项。

## 何切训练

何切模块包括：

- 静态题库加载与启动时校验
- 精确答案判断，而不是仅凭近似得分接受多个答案
- 难度评分和按免费策略限制最高难度的能力
- 根据难度、弱项和近期题目多样性自适应选题
- 教学标签、候选牌分析和反馈面板
- 超时、跳过、错误和正确结果的明确状态
- 何切技能掌握度设备本地持久化

题库文件为 `frontend/assets/data/nanikiru_puzzles.json`。修改后执行：

```powershell
Set-Location frontend
dart run tool/validate_nanikiru_puzzles.dart
flutter test test/nanikiru_catalog_test.dart
```

## 间隔重复与闪卡

SRS 使用稳定内容 ID 保存复习项目，记录到期时间、复习次数和学习状态。写操作通过存储边界串行化，训练计划和复习队列共享被接受的作答事件，减少重复计数和并发写覆盖。

闪卡页面支持复习流程、反馈和训练计划进度；墓地页面用于管理需要重新学习的内容。

## 防守训练

防守模块覆盖现物、筋、壁牌等主题。每道题包含：

- 场面与河牌信息
- 可见牌统计
- 风险选项和风险标签
- 证据标签与解释代码
- 可校验的标准答案

进度模型按稳定技能 ID 保存正确、错误、跳过和超时结果，并记录近期错题引用，用于弱项推荐和继续训练。

## 役种测验

役种测验使用静态题库，支持：

- 根据牌型选择役种
- 判断番数
- 判断成立条件真伪

题目、答案和用户可见文案分离。领域层使用枚举 key，界面层映射到 ARB 本地化文本，避免把英文字符串写死在数据层。

## 手牌分析器

手牌分析器允许用户选择牌张并计算：

- 当前向听数
- 有效进张与剩余数量
- 14 张手牌下的弃牌候选
- 各弃牌后的向听数和有效牌比较

近期分析历史保存在设备本地，收藏记录不会被普通的历史容量淘汰。历史存储不可用时，当前分析仍可继续使用。

## 商业功能与免费发行

商业功能策略由四个编译时开关控制：

- iOS 是否允许新销售
- Android 是否允许新销售
- 是否启用免费用户红心和难度限制
- 是否允许恢复历史购买

销售与训练限制相互独立。默认版本关闭新销售、关闭训练限制、保留移动端恢复入口，因此应用可以在没有可用收款方式时作为完全免费版本发布。

Premium 状态只有在销售或训练限制真正需要时才主动解析；仅恢复模式保持懒加载，避免普通页面无意义连接商店。

商品 ID 属于客户端代码、商店后台和服务端校验之间的稳定契约，不能在控制台中任意改名。重新开放销售前需要联合验证三端配置。

## 后端与安全边界

FastAPI 服务在启动阶段验证生产配置并初始化 Firebase。生产环境要求：

- Firebase 服务账号配置完整
- RevenueCat webhook secret 完整
- 调试模式关闭
- 开发认证绕过关闭

受保护 API 验证 Firebase Bearer token。开发绕过只能由显式开关开启，并且生产环境会强制拒绝。

麻将 API 提供向听数和有效牌计算。输入在进入引擎前进行牌张格式、数量和重复张数校验，避免无效牌组进入计算。

## 自动化与发布边界

GitHub Actions 的职责：

- PR：运行 Flutter 和后端检查
- `main`：重新运行检查，并触发 Android 与 iOS 构建
- Android：产出 AAB、APK，保留 30 天，并把 AAB 上传到 Google Play internal track
- iOS：产出 IPA，保留 30 天，并上传 TestFlight

自动上传不等于自动通过商店审核，也不等于已经向所有用户正式发布。轨道、审核状态、国家/地区和分阶段发布比例需要在对应商店控制台确认。

## 当前已知边界

- UI 目前提供英语、法语和德语，不包含中文 ARB。
- 客户端网络层已经提供通用接口，但部分重试逻辑仍是占位实现；接入新的线上关键流程前必须补全并测试。
- 核心训练是设备本地优先，跨设备同步不能从本地存储能力自动推断。
- 收款方式和商店商品可用性属于外部控制台状态，不能只通过客户端代码判断。
