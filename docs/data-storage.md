# 数据与持久化

## 数据所有权

当前应用以设备本地训练为主。不同数据的权威来源如下：

| 数据 | 当前权威来源 | 是否持久化 |
|---|---|---:|
| 每日训练计划与连续记录 | 客户端 JSON 文件 | 是 |
| SRS 复习项目 | 客户端 JSON 文件 | 是 |
| 何切技能掌握度 | 客户端 JSON 文件 | 是 |
| 防守技能进度 | 客户端 JSON 文件 | 是 |
| 手牌分析历史与收藏 | 客户端 JSON 文件 | 是 |
| 红心、偏好、役种收藏 | Hive / 本地偏好 | 是 |
| 订阅状态原型 | 服务端进程内存 | 进程重启丢失 |
| 分析指标原型 | 服务端进程内存 | 进程重启丢失 |
| 排行榜 | Firestore；失败时进程内存 | 条件性持久化 |

## 本地键值数据库

应用启动时打开：

- `prefs`
- `hearts`
- `yaku_favorites`

认证服务还会按需打开 `auth`。Hive 用于适合按键读取的简单状态，例如语言、设置、收藏和红心状态。

不要在没有迁移方案时重命名 Box 或 key。Box 名称改变会让已有用户看起来像“数据消失”。

## 结构化文件存储

`StorageService` 使用应用文档目录保存 JSON：

- 简单整数和字符串集中在 `prefs.json`。
- 复杂对象保存为独立的 `<键名>.json`。
- 写入时先生成同目录 `.tmp` 临时文件并校验内容。
- 原有效文件被移动为 `.bak` 后，再通过重命名提交新文件。
- 读取不会采用未提交的 `.tmp`；主文件损坏时会尝试 `.bak`。
- 同一个键的并发写入会排队，不同键可以并行。

关键文件：

| 键名 | 文件 | 内容 |
|---|---|---|
| `srs_items` | `srs_items.json` | SRS 项目映射 |
| `nanikiru_skill_mastery_v1` | `nanikiru_skill_mastery_v1.json` | 何切技能掌握度 |
| `daily_training_plan_v1` | `daily_training_plan_v1.json` | 当日计划、进度和连续记录 |
| `defense_progress_v1` | `defense_progress_v1.json` | 防守技能和错题进度 |
| `hand_analysis_history_v1` | `hand_analysis_history_v1.json` | 最近分析与收藏 |
| 简单值集合 | `prefs.json` | 当前主要保存 ELO，也可承载明确接入的简单整数或字符串 |

## 数据版本

带 `_v1` 后缀的键是明确的数据格式版本。升级格式时：

1. 新模型必须能区分旧版本和新版本。
2. 先实现旧数据读取和迁移测试。
3. 迁移成功后再写入新键或新版本。
4. 不要直接复用旧键写入不兼容结构。
5. 迁移失败时保留原文件，不覆盖唯一副本。
6. 文档、测试和版本变更记录必须同步更新。

领域枚举不能直接依赖 `index` 长期持久化。何切和防守模块使用稳定字符串技能 ID，就是为了允许以后调整枚举顺序。

## 写入一致性

对于训练进度，推荐顺序是：

```text
验证作答是否被接受
  → 更新模块进度
  → 更新每日计划
  → 更新 SRS（如适用）
  → 等待关键写入完成
  → 再离开页面或显示持久完成状态
```

高级 Store 会执行写后读校验。底层 `StorageService` 为了保持应用可用性，会捕获文件系统错误；因此需要严格持久化保证的模块不能只调用写入后立即假设成功。

## 网页平台限制

`StorageService` 的文件存储在 Web 平台没有应用文档目录。当前主要目标是 iOS 和 Android；如果正式支持 Web，必须实现 Web 专用持久化适配器，不能沿用文件系统假设。

## 备份、恢复与卸载

- 数据主要位于系统分配的应用目录。
- 用户卸载应用后，本地数据是否保留取决于平台备份策略，代码不能假设一定保留。
- 当前没有完整的账号级跨设备同步。
- 购买恢复只恢复商店权益，不等于恢复训练历史。

## 云端数据库

当前明确使用的集合：

- `rankings`：文档 ID 为玩家名称，字段包括 `name`、`elo`、`streak`、时间戳。

现有排行榜设计适合原型，但生产化前需处理：

- 玩家名称碰撞和非法字符
- 认证用户与排行榜记录绑定
- 防作弊和服务端可信分数
- 索引、分页和查询成本
- 删除、匿名化和隐私请求
- 内存降级数据回写策略

## 隐私与敏感数据

- 不在本地日志输出购买凭证、Firebase 身份令牌或服务账号信息。
- 不把真实邮箱、私钥、商店密钥写入测试夹具或截图。
- 分析事件只收集完成业务所需的最少字段。
- 新增用户数据前，需要同步隐私政策、数据安全表单和删除流程。
