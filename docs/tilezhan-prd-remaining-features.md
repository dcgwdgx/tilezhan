## 一、何切复盘面板

### 用户场景
小明做了一道何切题，选了 3m 打出去——结果错了。他看到了正确答案是 7p，但**不知道为什么 7p 比 3m 好**。没有复盘面板，这道题等于白做。

### 核心目标
**让用户理解"为什么这个牌该打、那个牌不该打"。** 把隐性的牌效直觉变成可视化的数据。

### 显示内容

| 信息 | 说明 | 优先级 |
|------|------|:--:|
| 正确/错误标记 | 大字显示 ✅ Correct / ❌ Incorrect | P0 |
| 已选弃牌 & 最优弃牌 | 两张牌并排对比，高亮差异 | P0 |
| 向听数变化 | 打出每张牌后手牌的向听数是否降低 | P0 |
| 进张数对比 | 打出每张牌后，有多少种牌能让你进入听牌 | P0 |
| 可视化评分条 | 用进度条直观展示每张弃牌的优劣 | P1 |
| 一句话说明 | "7p is an isolated tile that doesn't break any meld" | P1 |
| 关键搭子高亮 | 在手牌图片里高亮哪些是搭子、哪些是孤张 | P2 |

### 交互流程

```
何切完成（正确/错误/跳过）
    │
    ▼
斜切动画 + "✅ Correct!" / "❌ Incorrect!"
    │
    ▼
0.5s 后自动展开复盘面板（底部向上滑入）
    │
    ▼
显示进张对比表 + 一句话说明
    │
    ├─ [下一题] → 生成新题，面板收起
    ├─ [再看一次] → 面板保持，手牌重新展示
    └─ [分享] → 截图分享复盘结果
```

### 不做什么
- 不显示所有 14 张牌的完整列表（太多信息）——只显示用户选的、正确答案、和另外 1-2 个接近的选项
- 不做 AI 大段解释——一句话够用
- 不在闪卡上做复盘（闪卡是记忆训练，不需要）

## 二、番型详情页

### 用户场景
小红在 Scanner 页面看到了 "Honitsu（混一色）"，想知道这到底是什么。她点进去，看到牌型示意图、得分条件、实战例子——理解了，下次打牌会注意。

### 核心目标
**从"知道名字"到"能在实战中认出来"。**

### 页面结构

```
导航栏: ← 返回   Honitsu    ⭐ 收藏
──────────────────────────────────
┌─ 基础信息 ──────────────────────┐
│ 混一色 (Half Flush)              │
│ Han: 3 (2 closed)               │
│ Difficulty: ★★☆☆☆ (Intermediate) │
└────────────────────────────────┘

┌─ 牌型示意 ──────────────────────┐
│ [牌面图片: 完整牌型示例]          │
│ 🀇🀈🀉 🀐🀑🀒 🀝🀞🀟 🀅🀅     │
│ 一个花色 + 字牌，不允许混其他花色  │
└────────────────────────────────┘

┌─ 成立条件 ──────────────────────┐
│ ✅ 只有一种数牌花色              │
│ ✅ 可包含任意数量的字牌           │
│ ❌ 不能包含第二种数牌花色         │
│ ⚠️ 门前清时 2 Han，副露后降为 1 Han │
└────────────────────────────────┘

┌─ 常见组合 ──────────────────────┐
│ 混一色 + 对对和 = 5 Han          │
│ 混一色 + 一気通貫 = 6 Han        │
│ 混一色 + 役牌 ×2 = 4 Han         │
└────────────────────────────────┘

┌─ 实战笔记 ──────────────────────┐
│ "当你手上有 7 张以上同一花色时，  │
│  认真考虑做混一色。扔掉其他花色的  │
│  孤张牌，保留字牌作役牌。"        │
└────────────────────────────────┘
```

### 数据来源
现有 `assets/data/tiles.json` 已有 34 牌数据。役种数据需要新增一个 `yaku_data.json` 或直接写在代码里（日麻常见役种约 30 个）。

### 触发入口
- Scanner 页点役种 → 详情页
- Collection 页点已解锁役种 → 详情页
- 将来复盘面板里可以关联到相关役种

### 不做什么
- 不显示真人牌局录像（MVP 做不动）
- 不做交互式模拟（太复杂）
- 收藏功能先放按钮，后端没做完前用本地 Hive 存

## 三、排行榜

### 用户场景
小刚连续练了一周，想知道自己在所有用户里什么水平。打开排行榜，看到自己排第 47 名——有动力冲到前 20。

### 核心目标
**通过社交竞争驱动留存。** 不求大规模社交，只求让用户有"被看见"的感觉。

### 功能设计

| 功能 | 说明 |
|------|------|
| 全局排名 | 按 ELO 降序，显示前 100 名 |
| 我的排名 | 登录后高亮自己的排名行；未登录显示"注册后查看排名" |
| 段位徽章 | 每行显示段位图标（Novice→Master） |
| 邀请入口 | 底部固定按钮"邀请好友一起冲榜" |

### 排名计算
```
ELO = 基础分 800 + (正确数 × 10) - (错误数 × 5) - (跳过 × 3)
```

数据来源：后端 `/api/v1/srs/review_due` 返回的数据聚合。或者新增一个 `/api/v1/leaderboard` 端点。

### 交互流程

```
首页 / Profile 页 → 点"排行榜"入口
    │
    ▼
加载排行榜（从后端拉取）
    │
    ├─ 有数据 → 显示列表，高亮自己
    ├─ 无数据 → 显示空状态 "Be the first to rank!"
    └─ 加载失败 → 显示重试按钮
```

### 后端接口

```
GET /api/v1/leaderboard?limit=100
Response:
{
  "rankings": [
    {"rank": 1, "name": "PlayerX", "elo": 2480, "rank": "master"},
    ...
  ],
  "me": {"rank": 47, "name": "You", "elo": 1248, "rank": "adept"}
}
```

### MVP 简化
- 排行榜数据暂存在服务器内存（和 subscription_store 一样模式）
- 前端每次心脏跳时上报自己的 ELO，服务器计算排名
- 不去重、不分页、不做周榜/月榜——只有总榜

### 不做什么
- 不加好友系统（V2）
- 不做 PVP 对战（V2）
- 不做分地区榜（V2）
